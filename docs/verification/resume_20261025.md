# RESUME-R1: timeout resume while powered

In Reliable (ACK) mode, leave the receiver listening after TX fails and transmit
the same file again using the existing GUI control. The new attempt resumes at
the receiver's verified saved position. Existing 1-second DATA ACK wait, ten
retries and 20-second idle limits remain. Both firmware profiles need updating;
the existing NOACK-GUI-R4 executable is compatible and unchanged.

Resume applies before or after receiver idle timeout. The latest partial is
closed on timeout and retained with RAM metadata. Before appending, its exact
length and content CRC are checked against the accepted prefix. Final size/CRC
checks and atomic publication remain mandatory. An already published matching
file is verified again to recover a lost COMPLETE without creating a duplicate.
File identity uses size, packet count, CRC32 and final suffix; it does not include
the full original filename and is not cryptographic authentication.

Only one latest receive is remembered. Both boards must remain powered; the
receiver must remain in Reliable receive mode. Stop/cancel, RX teardown, channel
or mode changes, and restart clear the checkpoint. Different metadata while
active remains Busy; after timeout it starts fresh. A missing or damaged partial
also restarts from zero. No-ACK mode cannot resume. Receive status may continue
to show Failed/Timeout until the next START arrives; this terminal status does
not delete the retained Reliable partial.

Software acceptance includes production receive dispatch/storage with real test
files and real sender/service: 57 cases per hardware profile, zero through maximum
1,310,720 bytes, prefix at zero/middle/EOF, retry before/after timeout, lost ACK,
stale old-ID cancellation, missing/extra/truncated/corrupt partial, changed
size/CRC/suffix, explicit Stop, lost COMPLETE, changed/deleted published file,
invalid READY offset, exact bytes and CRC/publication with no duplicate saves.
The native suite and prior production no-ACK/receive-guard/metadata/host suites
are retained. Final actual results and exact hashes are recorded in the workspace
outputs/rf3-resume-20261025 package manifest and logs.

No board connection, flashing or physical RF qualification is included. The user
performs manual BOOT/EN flashing with the supplied per-board helpers. The saved
before/ package and its Firmware_Images.json retain rollback image identities;
use Flash_Manual.ps1 -Version Previous -PreviousRoot pointing to that directory.

Session replay protection remembers up to 32 retired attempt IDs per checkpoint.
If that limit is reached, a fresh ID is rejected Busy without evicting history.
Use Stop, then Receive to start fresh in that unusual case. Old START packets
cannot reclaim a resumed checkpoint, including after damaged-file fallback.
